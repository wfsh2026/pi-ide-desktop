# pi-ide-desktop 功能优化开发计划

更新时间：2026-05-12

## 目标

基于当前 `pi-ide-desktop` 已有功能，对标主流 AI Coding IDE 的使用体验，整理后续可优化方向。

当前产品已经具备：

- Pi CLI 桌面终端承载
- 项目与多会话管理
- 目录树与文件搜索
- 文件拖拽与会话附件
- AI 参考文件 / AI 输出文件追踪
- 黑灰中性风格基础配色

后续优化重点应从“终端壳”逐步升级为“结构化 AI Coding IDE”。

## P0 详细计划

### 1. 会话视图 / 终端视图切换

#### 当前状态

当前中央区域主要是 xterm 终端，Pi 输出、工具调用、结果都混在终端文本中。

#### 问题

- 用户消息和 AI 回复边界不清晰。
- 工具调用和工具结果不易折叠。
- 长会话回看困难。
- 与结构化 AI Coding UI 有差距。

#### 建议实现

新增顶部或终端区域内的视图切换：

```text
[会话视图] [终端视图]
```

会话视图展示：

```text
用户消息
AI 回复
工具调用 read src/App.jsx
工具结果，可折叠
文件输出卡片
变更摘要卡片
```

#### 技术方案

优先考虑两种来源：

1. 使用 Pi `--mode json` 获取结构化事件。
2. 继续扩展当前 `.pi/extensions/pi-ide-file-tracker.ts`，让它输出更多结构化事件。

---

### 2. 右侧 Git 变更 / Diff 验收面板

#### 当前状态

当前右侧已有：

- 目录树
- 会话文件

但还没有 Git 变更验收能力。

#### 目标

新增右侧工具：

```text
变更
```

展示：

```text
当前分支 master
3 个文件已更改
README.md +279 -0
src/App.jsx +20 -4
```

点击文件后可以：

- 查看 Diff
- 打开文件
- 复制 Diff
- 复制路径
- 撤销单文件改动，可选

#### 后端命令建议

新增 Tauri command：

```rust
get_git_status(workdir)
get_git_diff_numstat(workdir)
get_git_diff_file(workdir, path)
copy_git_diff_file(workdir, path)
```

内部使用：

```bash
git status --porcelain
git branch --show-current
git diff --numstat
git diff -- path
```

### 3. 会话文件操作增强

#### 当前状态

已完成：

- 用户插入文件进入 AI 参考文件
- 目录树拖入文件进入 AI 参考文件
- Pi `read` 进入 AI 参考文件
- Pi `write/edit` 进入 AI 输出文件
- bash diff 检测输出文件

#### 建议增强

AI 参考文件：

- 打开文件
- 打开所在目录
- 复制路径
- 从会话文件中移除

AI 输出文件：

- 打开文件
- 打开所在目录
- 复制路径
- 查看 Diff
- 跳转到 Git 变更面板

### 4. 底部状态条增强

#### 当前状态

底部主要显示：

```text
当前项目 / 当前会话
```

#### 建议展示

```text

```

#### 价值

提升用户对当前执行环境的信任感，避免误操作。

## P1 详细计划

### 5. 文件事件监听从轮询改为事件推送

#### 当前状态

前端定时调用：

```js
invoke("load_pi_ide_file_events", { workdir })
```

#### 建议

Tauri 后端监听：

```text
当前项目/.pi/pi-ide-file-events.jsonl
```

有变化时主动：

```rust
app.emit("pi-file-event", event)
```

#### 收益

- 更实时
- 减少轮询
- 降低前端重复解析成本

---

### 6. 项目 / 会话数据迁移到后端 JSON 存储

#### 当前状态

项目和会话数据主要存在 localStorage。

#### 风险

- 长输出容易导致前端存储膨胀。
- 不方便备份。
- 不方便多窗口协作。

#### 建议

迁移到：

```text
~/.pi-ide/projects.json
~/.pi-ide/sessions/<project-id>.json
```

或者：

```text
~/.pi-ide/projects/<project-id>/sessions.json
```

---

### 7. 目录树懒加载

#### 当前状态

目录树一次性读取固定深度，已省略大目录。

#### 建议

改为点击文件夹时加载子目录：

```text
get_directory_children(path)
```

#### 收益

- 大项目不卡顿
- 深层目录可完整浏览
- 不需要固定最大深度

- 会话输出摘要

### 9. Pi 启动诊断

#### 建议检测项

```bash
pi --version
node --version
where pi
where node
echo %PATH%
```

同时检测：

- 当前工作目录是否存在
- `.pi/extensions/pi-ide-file-tracker.ts` 是否成功写入
- 是否使用了 `--no-extensions`
- API Key 是否存在


#### 建议

提供表单：

```text
Provider: DeepSeek
API Key: ********
启动参数: -nc
```

## 推荐下一步落地顺序

| 阶段 | 建议任务 | 原因 |
|---|---|---|
| 第一阶段 | Git 变更 / Diff 验收面板 | 最接近结构化验收体验，用户价值最高 |
| 第二阶段 | 会话文件操作增强 | 与现有 AI 参考文件 / 输出文件能力直接衔接 |
| 第三阶段 | 底部状态条增强 | 提升可感知状态和信任感 |
| 第四阶段 | 会话视图 / 终端视图切换 | 产品体验升级最大，但实现复杂度也最高 |
| 第五阶段 | 文件事件监听替代轮询 | 技术架构优化，降低长期维护成本 |

## 当前建议优先启动

建议优先启动：

```text
Git 变更 / Diff 验收面板
```

原因：

1. 与参考图中的“生成结果 / 文件已更改”最接近。
2. 对用户验收 AI 修改最有帮助。
3. 技术实现相对清晰，可独立交付。
4. 能直接复用当前 AI 输出文件追踪结果。
